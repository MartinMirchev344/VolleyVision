## Project scope and collaboration

The ABLE Mentor showcase covers player detection, anonymous tracking, and movement heatmaps. Player recognition means detecting players, not identifying names or jersey numbers. Heatmaps are part of the showcase and follow the detection and tracking baseline.

## 1. Vision

VolleyVision is a computer-vision application for **volleyball player detection, multi-object tracking, and match movement visualization** from existing match recordings. The initial target is **fixed-camera, behind-the-end-line footage**, with elevated sideline footage also acceptable. It is being built as an **ABLE Mentor showcase**, an **AI/ML engineering portfolio project**, and potentially a **commercial product for volleyball clubs**.

The immediate goal is **learning and a small, defensible working demonstration**, not a feature-complete sports analytics platform. The developer is comfortable with Python and has trained ML models before, but wants to understand each major AI concept before implementing it.

### Success criteria for v0.1

- Accept a local MP4 video from an existing recording.
- Detect visible volleyball players using a pretrained object detector.
- Track detections across frames with temporary, persistent IDs where possible.
- Export an annotated MP4 and machine-readable per-frame tracking data (CSV or JSON).
- Generate movement heatmaps after the tracking baseline; optionally display player trails and tracking coverage statistics.
- Run locally on an NVIDIA **RTX 5070, 12 GB GDDR7**.
- Provide reproducible setup, tests, evaluation instructions, and an honest limitations section.
- Be demo-ready even without a web interface or fine-tuned model.

### Explicit non-goals for v0.1

- Identifying players by name or jersey number.
- Ball tracking, spike/set/block classification, or automatic tactical recommendations.
- Reliable statistics across camera cuts, moving cameras, or multiple courts.
- Precise running distances or performance scores without validated court calibration.
- Real-time streaming, accounts, payments, cloud deployment, or SaaS infrastructure.

## 4. Architecture

```text
Input MP4
   |
   v
Video reader / frame sampler (OpenCV)
   |
   v
Player detector (pretrained YOLO-family baseline)
   |
   v
Multi-object tracker (ByteTrack baseline)
   |                     \
   v                      v
Annotated video writer   Tracks CSV/JSON
   |
   v
Optional movement trails / summary report

Showcase after tracking: movement heatmaps; court calibration for top-down positions
Later: labeled dataset -> fine-tuned detector -> comparative evaluation
```

### Preferred stack

- Python 3.11 or compatible stable version.
- PyTorch with a CUDA build that supports RTX 5070; verify availability rather than assuming.
- OpenCV for video I/O and overlays.
- Ultralytics YOLO-family detector for **research prototype only**, subject to licensing review.
- ByteTrack as initial tracking baseline, through a documented integration.
- NumPy, pandas, pytest, and a minimal CLI (`argparse` or Typer).
- Optional Streamlit interface **after** CLI works.

**Model selection:** Verify the current officially supported checkpoint and hardware compatibility when implementation begins. A small pretrained YOLO-family model is the baseline; do not hardcode a specific model name in the design. Compare a larger model only if there is a demonstrated need.

## 6. Data policy and camera setup

### Video sources

Use **existing recordings for which the owner has permission**. Public availability on YouTube does not itself authorize downloading, extracting training frames, redistributing them, or commercial use. Track source, owner, permission, license, commercial rights, and publication restrictions in a private dataset manifest.

Do not publish videos of identifiable players, particularly minors, without appropriate permission. Keep raw videos and annotation exports out of Git.

### Camera setup for future recordings

Never place a tripod or camera in the volleyball free zone or where players can collide with it. Prefer elevated spectator seating, a balcony, or a position behind a protective barrier with venue approval. Avoid loose cables, blocked exits, or improvised overhead mounts. For the MVP, **do not require new recordings**.

### Initial dataset strategy

1. Inventory existing recordings: filename, source/permission, resolution, FPS, duration, camera angle, camera movement, visibility, lighting.
2. Choose 2–3 representative clips for qualitative baseline testing.
3. First run the pretrained detector **without fine-tuning**.
4. Only if necessary, annotate ~100–200 representative frames, later expanding to ~300+ as justified.
5. Use **match-level or recording-level** train/validation/test separation; never random-split adjacent video frames.
6. For tracking evaluation, label **consecutive sequences with consistent ground-truth IDs**, not isolated images.
7. Record labeling conventions for players, referees, spectators, occlusion, and partially visible people.

## 10. Evaluation requirements

### Detection

- Metrics: precision, recall, mAP50, mAP50-95 on annotated, held-out footage.
- Report model checkpoint, confidence threshold, input resolution, dataset split, and FPS.
- Compare pretrained versus fine-tuned **only after a fine-tuned model exists**.

### Tracking

- Annotate short consecutive sequences with consistent ground-truth identities.
- Use IDF1, HOTA, and number of ID switches when evaluation tooling and annotations permit.
- Document failure cases: occlusion, similar uniforms, camera cuts, players leaving/reentering view, spectators, referees.
- Tracker IDs are **temporary anonymous IDs**, not guaranteed real player identities.

### Runtime

- Measure actual processing FPS, total runtime, video length, GPU model, and peak VRAM if available.
- Benchmark on the same video and configuration when comparing implementations.
- Do not invent performance numbers or claim real-time operation without evidence.

### Analytics caveat

Movement trails in image coordinates are acceptable for v0.1. Do not report real-world distances or tactical conclusions without validated court mapping and error estimates.
